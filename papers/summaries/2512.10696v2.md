# Remember Me, Refine Me: A Dynamic Procedural Memory Framework for Experience-Driven Agent Evolution

## Metadata
- **Authors:** Zouying Cao, Jiaji Deng, Li Yu, Weikang Zhou, Zhaoyang Liu, Bolin Ding, Hai Zhao
- **Venue:** arXiv preprint
- **Year:** 2026
- **Links:** [Paper](https://arxiv.org/abs/2512.10696) | [Code](https://github.com/agentscope-ai/ReMe)
- **PDF:** `../papers/pdfs/2512.10696v2.pdf`

## Summary

Existing procedural memory frameworks treat experience as a static append-only archive — they store trajectories or summaries, retrieve them, but never systematically prune or adapt them over time, causing the pool to degrade into a mix of valid insights and "toxic noise." This paper proposes **ReMe** (*Remember Me, Refine Me*), a dynamic procedural memory framework built around three coordinated phases. *Experience Acquisition* distills agent trajectories into structured fine-grained keypoint-level experiences via three complementary analyses: success pattern recognition (what worked and why), failure analysis (earliest failure step), and comparative insight generation (what distinguished high- vs. low-scoring trajectories). Each experience is stored as a structured tuple E = ⟨ω, e, κ, c, τ⟩ (usage scenario, content, keywords, confidence score, tools used), indexed by usage scenario embeddings for retrieval. *Experience Reuse* retrieves the top-K most similar experiences at task start, optionally reranking and rewriting them into cohesive task-specific guidance. *Experience Refinement* maintains the pool by selectively adding only successful experiences, running failure-aware reflection (failed execution → new trial with lessons → add if successful), and periodically deleting experiences whose utility-to-retrieval ratio falls below threshold β.

Evaluated on BFCL-V3 and AppWorld with Qwen3 models (8B, 14B, 32B) and six additional LLMs, ReMe achieves state-of-the-art performance, with average gains of +8.83% Avg@4 and +7.29% Pass@4 for Qwen3-8B. The key headline result is a **memory-scaling effect**: Qwen3-8B + ReMe (dynamic) exceeds vanilla Qwen3-14B (55.03% vs. 54.65% Pass@4), and Qwen3-14B + ReMe (dynamic) exceeds vanilla Qwen3-32B (Avg@4: 44.66% vs. 40.89%). Ablations confirm: keypoint-level extraction strongly outperforms trajectory-level; selective addition (success-only) beats full addition; usage scenario indexing beats raw task description or keyword retrieval; and dynamic refinement consistently beats a fixed memory pool.

## Relevance to Thesis

Directly relevant to all three thesis focus areas:

- **Memory Controller**: ReMe's structured experience format E = ⟨ω, e, κ, c, τ⟩ is a concrete, implementable schema for procedural memory. The three-phase lifecycle (Acquire → Reuse → Refine) with utility-based deletion is a strong design template. The usage scenario indexing insight (LLM-generated scenario field beats raw task query) is directly applicable to retrieval design.

- **Educability**: Failure-aware reflection — where a failed experience triggers a new trial that, if successful, gets added to memory — operationalizes online self-correction. The comparative insight extraction (analyzing what distinguished high- from low-scoring trajectories) is a structured form of learning from contrast, directly relevant to teaching-signal design.

- **Knowledge Transfer**: The memory-scaling effect (smaller model + memory > larger model without) is a direct demonstration of procedural knowledge compensating for parameter count — a key thesis claim. Also shows the importance of a stronger summarizer (LLMsumm > LLMexecute) for knowledge extraction quality.

Strong baseline to compare against for procedural memory controller design. Released dataset `reme.library` is directly usable for thesis experiments.

## Method Details

**Architecture:**
- Summarizer LLM (LLMsumm) analyzes trajectories → structured experiences
- Experience pool: vector database (Elasticsearch), indexed by Qwen3-Embedding embeddings of usage scenario field
- Retrieval: top-K cosine similarity → optional LLM reranker → optional LLM rewriter for task-specific guidance
- Utility tracking: each experience records total retrievals f and utility u (incremented when retrieval → task success); deleted when f ≥ α and u/f < β

**Training/Setup:**
- No fine-tuning; entirely prompt-based at inference time
- N=8 trajectory samples per task during experience acquisition
- Top-K=5 for retrieval; max 3 self-reflections per failure
- Utility thresholds: α=5, β=0.5
- LLMsumm = LLMexecute in main experiments (self-evolution)

**Evaluation:**
- BFCL-V3: Avg@4 (average success rate across 4 trials) and Pass@4 (probability ≥1 of 4 trials succeeds)
- AppWorld: Task Goal Completion (TGC)
- Results averaged over 3 independent runs

## Gaps & Open Questions

### Limitations (acknowledged)
- Fixed retrieval strategy: experiences retrieved only once at task start; no dynamic in-context retrieval
- LLM-as-judge validation may miss nuanced quality issues and is expensive at scale
- Single-failure reflection may be insufficient when inherent model limitations are the cause

### Limitations (observed)
- No cross-domain transfer tested (does an BFCL memory pool help on AppWorld?)
- No analysis of how the experience pool evolves over time (does quality plateau? at what size?)
- Rewriting module adds latency — no latency breakdown beyond the +2.54s overhead reported for AppWorld
- All Qwen3 backbones; generalizability to other model families (Llama, Mistral) not tested in main experiments

### Unexplored Directions
- **Multi-task memory pools**: Can a single experience pool trained on diverse tasks generalize better than task-specific pools?
- **Cross-model memory transfer**: Can experiences extracted by Qwen3-32B (stronger summarizer) be used to bootstrap Qwen3-8B? (Table 5 shows stronger LLMsumm helps — test across model families)
- **Hierarchical experiences**: Current keypoint-level experiences are flat; could a two-level hierarchy (abstract principle + concrete step) improve both generalization and precision?
- **Active forgetting policies**: Utility-based deletion uses fixed thresholds α, β — could these be learned or adapted per task domain?
- **POC**: Implement ReMe's experience structure + utility-based deletion as thesis memory controller procedural layer; test memory-scaling effect with cross-model summarizer pairing.

## Notes
- ReMe is contemporaneous with MemP (2508.06433) and covers very similar territory. Key differences: ReMe uses structured keypoint-level experiences vs. MemP's trajectory+script combo; ReMe has utility-based deletion which MemP lacks; ReMe focuses on function-calling tasks vs. MemP's housework/travel planning. Worth comparing these two directly.
- The `reme.library` dataset (structured success patterns + failure lessons from diverse agentic tasks) is a valuable resource for training memory controllers or distillation experiments.
- Usage scenario indexing > raw task query is a surprising and practically important finding — the LLM-generated generalized scenario captures both context and application area, which raw descriptions miss.
