# Agentic Memory: Learning Unified Long-Term and Short-Term Memory Management for Large Language Model Agents

## Metadata
- **Authors:** Yi Yu, Liuyi Yao, Yuexiang Xie, Qingquan Tan, Jiaqi Feng, Yaliang Li, Libing Wu
- **Venue:** arXiv preprint
- **Year:** 2026
- **Links:** [Paper](https://arxiv.org/abs/2601.01885)

## Summary

Prior work treats Long-Term Memory (LTM) and Short-Term Memory (STM) as independent components — LTM via trigger-based or agent-based managers, STM via static RAG. This leaves both under-optimized and poorly coordinated. This paper proposes **AgeMem** (*Agentic Memory*), a unified framework that integrates both LTM and STM management directly into the agent's policy via a tool-based interface. The agent autonomously invokes six memory tools: ADD, UPDATE, DELETE for LTM; RETRIEVE, SUMMARY, FILTER for STM. Training uses a **three-stage progressive RL strategy** (GRPO): Stage 1 builds LTM from casual conversation context; Stage 2 trains STM control under injected distractors (context reset, LTM persists); Stage 3 requires coordinated retrieval and reasoning to complete the target task. A **step-wise GRPO** broadcasts the terminal trajectory reward back to all timesteps, enabling long-range credit assignment across heterogeneous memory operations. The composite reward covers task completion, context compression efficiency, and memory quality (storage relevance, maintenance operations, semantic alignment to query).

Evaluated on 5 long-horizon benchmarks (ALFWorld, SciWorld, PDDL, BabyAI, HotpotQA) with Qwen2.5-7B-Instruct and Qwen3-4B-Instruct, AgeMem achieves the highest average performance across all settings (41.96% and 54.31% respectively), with +49.59% and +23.52% relative gains over no-memory baselines. RL training alone contributes ~8.5 percentage points over AgeMem without RL (AgeMem-noRL). Memory Quality scores (MQ) on HotpotQA are 0.533 and 0.605 — highest among all baselines including LangMem, A-Mem, Mem0. STM tools reduce token usage 3.1–5.1% vs. RAG, and the all-returns composite reward produces substantially higher MQ than task-only reward (0.533 vs. 0.479).

## Relevance to Thesis

Directly addresses all three thesis focus areas at a deep level:

- **Memory Controller**: AgeMem is the most technically sophisticated memory controller design in the thesis library. The 6-tool interface (ADD/UPDATE/DELETE/RETRIEVE/SUMMARY/FILTER) is a complete, implementable action space for unified memory management. The three-stage trajectory structure separates memory acquisition, context filtering, and task execution into learnable sub-policies — directly informative for thesis memory controller architecture.

- **Educability**: The three-stage progressive RL strategy is a curriculum that teaches memory behavior from scratch — Stage 1 (store), Stage 2 (filter noise), Stage 3 (coordinate and reason). The step-wise GRPO that connects terminal task reward to early memory decisions is an educability mechanism: the agent learns *which memory operations lead to better outcomes* purely from task-level feedback. This is a strong model of learning-from-experience at the policy level.

- **Knowledge Transfer**: The RL-trained memory policy generalizes across 5 diverse benchmarks despite training only on HotpotQA — a strong cross-domain transfer result. The memory quality metric shows that RL improves not just task performance but the relevance of what gets stored. The tool usage analysis shows how RL changes memory behavior (more ADD/UPDATE, more FILTER, more balanced RETRIEVE).

Is a methodological baseline for the thesis — specifically for training memory management policies via RL.

## Method Details

**Architecture:**
- 6 memory tools: LTM tools (ADD, UPDATE, DELETE) + STM tools (RETRIEVE, SUMMARY, FILTER)
- Agent state: st = (Ct, Mt, T) — short-term context + long-term memory store + task specification
- Action space: language generation OR memory tool calls (structured JSON)
- Tool interface exposed via system prompt with strict <think>/<tool_call>/<answer> format

**Training:**
- Base models: Qwen2.5-7B-Instruct and Qwen3-4B-Instruct
- RL trained only on HotpotQA training set; evaluated zero-shot on all 5 benchmarks
- K=8 independent rollouts per task for group normalization (GRPO)
- 3-stage trajectory: Stage 1 (LTM construction from context Iq), Stage 2 (STM control under distractors Mdis with reset context), Stage 3 (integrated task q with full memory access)
- Step-wise GRPO: terminal reward R(τ) broadcast uniformly to all timesteps At^(k,q) = AT^(k,q)
- Composite reward: wtask=wcontext=wmemory=1/3; Ppenalty for overflow (-0.5) and round limit (-1.0)
- Context limit: 8,192 tokens; response limit: 2,048 tokens; max 30 iterations per task

**Evaluation:**
- Success Rate (SR) for ALFWorld, SciWorld, BabyAI
- Progress Rate (PR) for PDDL
- LLM-as-a-Judge (J) for HotpotQA
- Memory Quality (MQ): LLM-based relevance score of stored memories vs. ground-truth supporting facts

## Gaps & Open Questions

### Limitations (acknowledged)
- Fixed set of memory management tools — cannot support more fine-grained operations without redesign
- Evaluated on limited set of benchmarks relative to the diversity of real-world agent tasks

### Limitations (observed)
- RL training only on HotpotQA: may not learn optimal memory behaviors for spatial (ALFWorld) or planning (PDDL) tasks — the generalization is impressive but the training signal mismatch is a concern
- No analysis of how memory content evolves across a deployment session with many diverse tasks
- No ablation on number of RL training stages (what if you only do Stage 1+3, skipping Stage 2?)
- MQ metric evaluated only on HotpotQA (where ground-truth supporting facts exist) — no memory quality measurement on other benchmarks
- KL coefficient β=0.1 and uniform reward weights not ablated

### Unexplored Directions
- **Cross-model memory transfer**: Can AgeMem's trained memory policy transfer to a different model backbone? (RL-trained policy is model-specific)
- **Adaptive tool set**: Can the memory tools be augmented or specialized based on task type?
- **Memory quality as curriculum signal**: Could memory quality reward (Rmemory) be used independently as a teaching signal for a student agent?
- **Scaling the RL training set**: Training only on HotpotQA is a significant limitation — what happens with multi-domain RL training?
- **POC**: Implement AgeMem's 3-stage progressive RL as thesis training curriculum; compare to distillation-based approaches for teaching memory management.

## Notes
- This is the most technically ambitious paper in the current thesis reading list — RL-based unified memory management is the most principled approach but also most expensive to replicate
- The step-wise GRPO insight (broadcast terminal reward to all timesteps) is a simple but powerful mechanism for memory credit assignment — usable even outside AgeMem's framework
- Tool usage statistics (Table 3) are a goldmine: RL causes large increase in ADD (0.92→1.64) and first appearance of UPDATE/DELETE, and proactive FILTER (0.02→0.31) — shows exactly what behaviors RL teaches vs. what's already present without training
- The composite reward design (3 components × 3 subcomponents each) is careful but complex — the thesis could explore simpler reward designs that achieve similar outcomes
